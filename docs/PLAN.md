# LendLoop — Implementation plan

Companion to [DESIGN.md](./DESIGN.md), which records _what_ we decided. This file is _how and in what order_ we build it.

Guiding principle: **the required scope ships first, end to end; extras come last and can be cut.** Each phase ends in a working, committed state with its own verification step.


Effect boundaries:

- **Pure domain** (`shared/domain`) returns `Either` or tagged errors and has no services, so it's trivially testable.
- **Confect functions** are `Effect.gen` handlers using `CurrentUser`, the DB services and policies. Typed errors (`NotSignedIn`, `Forbidden`, `NotFound`, `InvalidTransition`, `DateConflict`, `RateLimited`) flow to the client as `_tag` unions.
- **Integration** consists of `N8nClient` (Layer) with `Schedule.exponential` + jitter, `Signature` as Effects over Web Crypto, and `AppConfig` via Effect `Config` (secrets as `Redacted`).
- **React**: Confect hooks. The UI branches on `error._tag` and never parses strings.

## Phase 0 — De-risk spike (do first, throw away anything ugly)

Prove the riskiest assumptions before building on them:

1. Next.js + bun + Confect v10 (Effect 4) + Convex cloud dev + Clerk wired together, with a "whoami" query returning the Clerk identity.
2. A Confect HTTP endpoint can read the **raw body + headers** (needed for HMAC). Fallback: a native `http.route` with `httpActionGeneric`, delegating to Effect.
3. `crypto.subtle` HMAC works in the Convex default runtime, so we don't need a Node action.
4. `docker compose up` brings n8n + resendev up, and n8n can reach resendev and reach Convex over the tunnel.
5. TanStack Form accepts our Effect Schema through Standard Schema.

**Exit:** a short note in DESIGN.md of anything that changed. **Needs you:** `bunx convex dev` login, a Clerk app, cloudflared or ngrok installed.

## Phase 1 — Foundation

- Scaffold Next.js (bun), strict tsconfig (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`).
- oxlint (no-explicit-any, no-unnecessary-type-assertion equivalents, react rules) and oxfmt. Scripts: `typecheck`, `lint`, `fmt`, `fmt:check`, `test`, `codegen`.
- Tailwind v4 + shadcn init with a minimal theme, plus base components (button, card, badge, dialog, select, calendar/date-range, table, sonner, skeleton).
- Providers: `ClerkProvider` → `ConvexProviderWithClerk` → Confect. Clerk middleware protects `(app)` routes, and Next proxy redirects only for UX, since Convex enforces access.
- `.env.example` (Next) and the documented Convex env vars list.

**Verify:** `bun run typecheck && bun run lint && bun run fmt:check` all pass in an empty app.

## Phase 2 — Domain (pure, tested first)

- Schemas: `Category`, `Condition` (literals plus label maps), `IsoDate` (branded, validated via Temporal), `DateRange` (start ≤ end, start ≥ today checked separately), `LoanStatus`.
- `loanTransitions`: a table of `{ from, action, allowedActor } → to`, with actions `request | approve | decline | cancel | markReturned`. Returns `Either<LoanStatus, InvalidTransition | Forbidden>`.
- `dateRange.overlaps`, `loanView.isOverdue(loan, today)`, `daysOverdue`, `toolAvailability(tool, loans, today)`.
- Unit tests for every transition × actor and the overlap edge cases (touching ranges, same day).

**Verify:** `bun test` is green, and this is the bulk of the domain coverage.

## Phase 3 — Data model, identity, RBAC

- Tables and indexes:
  - `users` (clerkId, email, firstName, role, trustedLender, anonymizedAt?) by_clerkId, by_email
  - `tools` (ownerId, name, category, condition, description, photoId?, archivedAt?) by_owner, by_category_archived
  - `loans` (toolId, borrowerId, lenderId (denormalized for indexes), startDate, endDate, status, decidedAt?, returnedAt?) by_tool_status, by_borrower, by_lender, by_status_endDate
  - `outboxEvents` (eventId, type, payload, status, attempts, nextAttemptAt, lastError?) by_status_nextAttempt
  - `automationEvents` (loanId?, kind, status, idempotencyKey, detail, at) by_key (unique by convention), by_loan
  - `trustAudit` (userId, grantedBy, action, at)
- Clerk webhook (`/webhooks/clerk`): svix verification, then upsert or anonymize the user. ADMIN_EMAILS bootstrap applies on create only.
- Middleware: `RequireUser` (provides `CurrentUser`, fails with `NotSignedIn` / `AccountNotProvisioned`) and `RequireRole({ admin: true })`.
- Policies: `requireToolOwner(toolId)` and `requireLoanParty(loanId, "lender" | "borrower")`, as Effects that fail with `Forbidden` / `NotFound`.

**Verify:** convex-test tests that a non-owner can't edit or delete, a non-admin can't call admin functions, and an anonymous caller is rejected everywhere except the public query.

## Phase 4 — Core backend features

- **Public**: `tools.public.list` returns only `{ name, category }[]` for non-archived tools (explicit projection, its own `returns` schema).
- **Tools**: `create`, `update`, `archive` (guard: no approved loan in progress; auto-cancel pending loans and enqueue notifications), `listBrowse({ category?, trustedOnly? })` (with availability plus owner `{ firstName, trusted }`, trusted sorted first), `get(id)`, `myListings`. Photos: `generateUploadUrl` plus server-side content-type and size checks on attach.
- **Loans**: `request` (validate dates, not own tool, tool not archived; rate-limited), `approve` (overlap check against approved loans; auto-decline overlapping pending loans), `decline`, `cancel`, `markReturned`, `myRequests`, `incoming`, `bookedRanges(toolId)`. Contact emails are revealed only on approved loans to the two parties.
- Every status change goes through `loanTransitions` and **calls `Outbox.enqueue` in the same mutation**.
- Rate limiter component: `requestLoan` 10/h per user, `createTool` 20/day per user.

**Verify:** tests for each mutation's happy path plus its forbidden, conflict and transition errors.

## Phase 5 — Frontend

- **Landing**: tagline, a public list grouped or filterable by category, sign-in CTA. Server-rendered via `preloadQuery` for a fast first paint.
- **Browse** `/tools`: a category filter and trusted toggle in the URL (nuqs), cards with an availability badge and trusted badge.
- **Tool detail**: info, booked ranges, request form (TanStack Form + Effect Schema), with the date picker disabling booked ranges.
- **My listings**: create and edit dialog, archive with a guard message, photo upload.
- **My requests / Incoming**: lists grouped by status with actions (cancel / approve / decline / mark returned) and an overdue highlight.
- Error UX: one `matchError(_tag)` → toast copy helper, and skeleton loading states.
- No `useEffect`. Everything is derived from query results and URL state.

**Verify:** a manual click-through of both roles in two browsers. Checkpoint: **all required non-n8n features are done.**

## Phase 6 — Outbox + Convex → n8n

- `Outbox.enqueue(tx, event)` inserts a `pending` row and calls `scheduler.runAfter(0, dispatch, { id })`.
- `dispatch` action (Effect):
  1. Load the row and build the minimal payload.
  2. Sign it.
  3. POST to `N8N_NOTIFY_WEBHOOK_URL` with an in-process `Schedule.exponential("500 millis").pipe(jittered, recurs(3))`, retrying only on network or 5xx errors.
  4. On success mark it `delivered`. On failure increment `attempts`, set `nextAttemptAt` with durable backoff and reschedule. After `MAX_ATTEMPTS` mark it `dead` and record an `automationEvent`.
- Sweeper cron (every 5 min): re-dispatch `pending` rows whose `nextAttemptAt` has passed, as a safety net against lost schedules.
- Headers: `X-LendLoop-Signature`, `X-LendLoop-Event-Id`. The canonical string is `t.METHOD.path.body`, so signed GETs work too, and it's documented in DESIGN.md.

**Verify:** unit tests for signature vectors. An integration test with a stub server returning 500 checks retries and dead-lettering.

## Phase 7 — n8n → Convex HTTP API

The `HttpApi` group `automation` sits behind an **HMAC middleware**. It verifies the timestamp tolerance, recomputes the signature over the raw request, compares in constant time, and returns 401 with no detail on failure.

- `GET /automation/overdue-loans`: Convex computes `today` in `APP_TZ` and returns loans that are approved, past their end date and have no `reminder:{loanId}:{today}` event. Minimal payload: `{ loanId, reminderKey, borrower: { email, firstName }, tool: { name }, endDate, daysOverdue }`.
- `POST /automation/reminders`: `{ reminderKey, loanId, status: sent | failed, providerMessageId? }`, upserted by `idempotencyKey`. A replay returns 200 with `{ duplicate: true }`.
- `POST /automation/errors`: `{ workflow, executionId, node, message }`, upserted by `executionId`.
- `POST /automation/notifications/ack` (optional): n8n confirms the email was sent for an `eventId`, which feeds the per-loan timeline.

**Verify:** tests for tampered body, stale timestamp, wrong secret and replayed write-back (exactly one row). curl scripts in `scripts/` for manual checks.

## Phase 8 — n8n workflows + local infra

- `docker-compose.yml`: `n8n` (env: secrets, `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`, `N8N_ENCRYPTION_KEY`, volume), `resendev`, and a `cloudflared` profile with a quick tunnel to n8n.
- Workflows (exported to `n8n/workflows/`):
  1. **Request notification**: Webhook (raw body) → verify signature (Crypto + compare) → Switch on `type` → set subject and body → HTTP Request to Resend (`Idempotency-Key: eventId`, retry 3× with backoff) → respond 200. Invalid signature returns 401.
  2. **Overdue reminders**: Schedule (daily 09:00 `APP_TZ`) → sign → GET overdue → Split → Resend (`Idempotency-Key: reminderKey`, retry) → sign → POST reminders `sent | failed` (continue on fail per item, so one bad email doesn't kill the batch).
  3. **Error handler**: Error Trigger → sign → POST `/automation/errors`. It's set as the error workflow on 1 and 2.
- Optional sub-workflow "Sign request" for DRY, if n8n's Execute Workflow keeps things readable.
- Export with `n8n export:workflow --backup` and a check script that greps the exports for secret patterns.

Idempotency is layered: the outbox `eventId`, then the Resend `Idempotency-Key`, then the Convex `idempotencyKey` upsert. A retry at any hop is safe.

**Verify:** the full loop. Create a request → email appears in resendev. Seed an overdue loan, run the reminder workflow manually → email plus "Reminder sent" in the app. Run it again → no duplicate. Kill resendev → retries, then an error report appears in the admin dashboard.

## Risks & mitigations

| Risk                                                           | Mitigation                                                                                                     |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Confect v10 / Effect 4 is new; docs and LLM knowledge are thin | Phase 0 spike. Fall back to plain Convex functions for specific pieces (Confect supports mixing).              |
| Raw body is unavailable in Confect HttpApi                     | Native `http.route` for the HMAC-protected routes, still Effect inside.                                        |
| Tunnel URL changes per run (quick tunnels)                     | Store `N8N_NOTIFY_WEBHOOK_URL` in Convex env and document the one command to update it. Named tunnel optional. |
| The Clerk webhook only reaches Convex once configured          | README step. The UI gate shows "setting up your account".                                                      |
| Scope creep                                                    | Required scope done at the end of phase 8. Phases 10–11 are cuttable.                                          |
